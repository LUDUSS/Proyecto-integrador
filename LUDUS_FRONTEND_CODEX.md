# LUDUS — Integración integral del frontend con backend existente

## Objetivo y forma de trabajo
Implementa en este repositorio frontend la integración completa de LUDUS con el backend Spring Boot y su catálogo IGDB. Inspecciona primero los archivos reales, el JS compartido y sus dependencias. No reconstruyas el sitio, no cambies el diseño ni la identidad visual: conserva HTML, CSS, Bootstrap, paleta, responsive, animaciones, cards, navbar, footer y textos estáticos útiles. Reutiliza las funciones existentes, modifica únicamente lo necesario y evita duplicar lógica entre pantallas. No cambies Java/MySQL ni endpoints; si algo no existe, documenta el bloqueo sin inventar datos. Ejecuta y verifica el trabajo en etapas, corrigiendo los errores hallados. No hagas commits ni borres datos reales o `localStorage` de usuarios.

Antes de comenzar, lee, si están disponibles en este repositorio, `docs/IGDB_API_CONTRATO.md` y `docs/IGDB_FRONTEND_GUIA.md` (originados en el repositorio backend). Si no están, utiliza el contrato esencial de abajo y anota la documentación faltante. Identifica primero los archivos actuales: `index.html`, `juegos.html`, `perfil.html`, `JS/api.js`, `JS/catalogoJuegos.js`, `JS/perfilUsuario.js`, `JS/resenias.js`, y sus archivos CSS; verifica nombres/rutas reales, no los asumas.

## Contrato backend esencial
Base local actual: `http://localhost:8080` (configurable). Todas las lecturas y escrituras nuevas de catálogo, perfiles y reseñas requieren JWT de LUDUS en `Authorization: Bearer <JWT_LUDUS>`; **no** usar Access Token/Client Secret de Twitch en navegador. `consumeApi(endpoint,{method='GET',body,auth=true})` ya adjunta JWT, serializa el objeto `body` y procesa JSON; pasa objeto JS, NO `JSON.stringify(body)`. Si se necesita distinguir 409/403/503, amplía errores de `consumeApi` conservando `status` y, si sirve, `Retry-After`; conserva compatibilidad con llamados existentes. No mostrar contraseñas o tokens en logs. Si 401, dirigir a login según flujo actual. Respeta CORS: backend actualmente autoriza origen 5502 localhost/127.0.0.1; si se corre otro puerto documentarlo.

- `GET /ludus/igdb/juegos?page=0&size=6&sort=rating` (explorar; sort `rating`, `lanzamiento`, `nombre`; filtros opcionales `genreId`, `platformId`).
- `GET /ludus/igdb/buscar?nombre=...&page=0&size=10&sort=relevancia` (búsqueda; filtros `genreId`, `platformId`; solamente sort `relevancia`).
- `GET /ludus/igdb/juegos/{igdbId}` (detalle).
- `GET /ludus/igdb/generos?page=0&size=20` y `/ludus/igdb/plataformas?page=0&size=20` (opciones con ID estable, páginas `hasNext`).
- Las listas devuelven `{items:[...],page,size,hasNext}`; NO son arrays ni incluyen conteo total.
- Game: `{igdbId,localGameId,nombre,descripcion,portadaUrl,generos:[{id,nombre}],plataformas:[{id,nombre}],lanzamiento,ratingIgdb,slug,screenshots:[...],ratingLudus:{promedio,cantidad}}`. `localGameId` puede ser null. `ratingIgdb` 0..100, rating LUDUS 1..5: no mezclarlos.
- `GET /ludus/publicacion/?page=0&size=6` -> reseñas recientes de todos los usuarios, ordenadas por fecha descendente.
- `GET /ludus/publicacion/juego/igdb/{igdbId}?page=0&size=20` -> reseñas del juego.
- `GET /ludus/publicacion/juego/igdb/{igdbId}/rating` -> `{promedio,cantidad}`.
- `POST /ludus/publicacion/igdb/{igdbId}` con `{texto,calificacion}` crea reseña y resuelve/guarda juego en MySQL automáticamente. No crear juego al navegar, buscar o abrir detalle.
- `PUT /ludus/publicacion/{idResenia}` con `{texto,calificacion}`; `DELETE /ludus/publicacion/{idResenia}` (204). Autor identificado exclusivamente con JWT, no enviar `idUsuario` ni email. Máximo **una** reseña por usuario/juego; duplicado devuelve 409; ofrecer editar/eliminar, nunca sobrescribir mediante POST. Evitar doble clic y reintentos automáticos de escrituras.
- Review: `{idResenia,texto,calificacion,fechaPublicacion,autor:{idUsuario,nombre},juego:{localGameId,igdbId,nombre,portadaUrl}}`.
- `GET /ludus/perfil/me`, `GET /ludus/perfil/{idUsuario}`, `PUT /ludus/perfil/me` body `{nombre,sobreMi}`.
- Profile: `{idUsuario,nombre,sobreMi,cantidadResenias,juegosResenados,promedioCalificacion,totalLikes}`.
- `GET /ludus/publicacion/me?page=0&size=20` y `/ludus/publicacion/usuario/{idUsuario}?page=0&size=20` (reseñas de perfil).
- Errores típicos 400 entrada, 401 JWT, 403 propiedad, 404 no encontrado, 409 duplicado, 502/503/504 IGDB no disponible. Portadas/descripciones pueden ser null. `lanzamiento` son segundos Unix UTC.

6. **Código compartido y robustez**: centralizar llamadas a catálogo, reseñas y perfiles sin duplicar funciones; usar `textContent`/DOM seguro para texto de usuarios/IGDB; imagen HTTPS y fallback; tratar 204 sin parseo, 401/403/404/409/503, peticiones fallidas y estados de carga. Mantener responsive y navegación existentes. Evitar exponer tokens o datos personales.
7. **Compatibilidad con datos previos**: `JS/catalogoJuegos.js`, `JS/perfilUsuario.js`, `JS/resenias.js` actualmente usan `localStorage` (`ludus_catalogo_resenias`, `resenias-videojuegos`, `perfil-usuario`) y `resenias.js` puede llamar `/ludus/resenia/` que NO existe. Sustituir esa fuente por la API; no borrar automáticamente ni importar silenciosamente los registros previos. Respaldos/importación de borradores sólo como trabajo separado consentido. No confundir `igdbId` con `localGameId`.
